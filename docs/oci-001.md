## 2. Justificación Técnica

### Problema Identificado

En las rutas Turbo-Necoclí se pierden señales celulares críticas que impiden:
- Procesar pagos en línea en tiempo real
- Validar transacciones inmediatamente con el servidor central
- Generar tiquetes QR con confirmación online

### Solución Propuesta

Implementar un sistema de pago QR offline que:
- Permite vender tiquetes a $18.000 COP sin conectividad
- Valida localmente con código QR NEQUI encriptado
- Sincroniza la transacción cuando regresa la señal
- Mantiene integridad referencial sin doble venta

### Riesgo Mitigado

**R1: Pérdida de señal en Turbo-Necoclí**
- Probabilidad: Alta
- Impacto: Crítico (paralización de ventas)
- Mitigación: SQLite local + Patrón Outbox + validación offline

### Especificación de Base de Datos

```sql
CREATE TABLE pagos_qr (
    id_pago SERIAL PRIMARY KEY,
    viaje_id UUID NOT NULL,
    asiento_numero INTEGER NOT NULL,
    monto DECIMAL(10,2) DEFAULT 18000.00,
    qr_nequi VARCHAR(255) UNIQUE NOT NULL,
    estado VARCHAR(20) DEFAULT 'PENDIENTE_SINCRONIZACION',
    timestamp_creacion TIMESTAMP DEFAULT NOW(),
    timestamp_sincronizacion TIMESTAMP NULL,
    usuario_id UUID NOT NULL,
    UNIQUE(viaje_id, asiento_numero)
);
```

### Estados del Pago QR

| Estado | Descripción | Transición |
| --- | --- | --- |
| PENDIENTE_SINCRONIZACION | Pago generado offline, aguarda señal | → SINCRONIZADO |
| SINCRONIZADO | Confirmado en servidor central | → ENTREGADO |
| ENTREGADO | Tiquete impreso o enviado por WhatsApp | Final |
| RECHAZADO | Validación fallida al sincronizar | → PENDIENTE_SINCRONIZACION (reintento) |
